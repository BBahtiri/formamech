# ADR 0032: Release 0.1.0

- Status: Accepted. The decision owner took decisions 1, 4 and 6 and signed off
  `limitations.md` (decision 10) on 2026-10-06. Decision 7 records the
  TestPyPI run when it happens.
- Date: 2026-10-06
- Step: S18 (gate `G18`, ⚑ human sign-off)
- Plan and results: [S18 release plan](../campaigns/s18-release-plan.md)

## Context

S18 releases what S0–S17 built. `G18` asks for eight things:

- every earlier gate passes;
- no shipped bundle claims more than `HOLDOUT_VERIFIED`;
- every adapted upstream component is recorded with its licence;
- the README is honest about the name;
- a valid citation file;
- an install from TestPyPI on three operating systems;
- a tool-generated lockfile;
- a tagged version with a changelog.

Before tagging, the decision owner must read the shipped `limitations.md` and
confirm every sentence is true of the code as built.

## Decisions

1. **Version 0.1.0** (decided). This is the first public release of an
   early-stage project, matching `pyproject.toml`, `CITATION.cff` and
   `piginot.__version__`.
2. **All earlier gates pass, three of them by recorded acceptance.** G0–G17
   are `PASS` in `artifacts/gates/` (notched-plate gates in
   `artifacts/campaigns/notched-v1/gates/`), with no `NOT_RUN`. Three passes
   rest on the decision owner's signed acceptances, and each records the
   computed result beside the acceptance:
   - the DogBone DEVELOPMENT budget (ADR 0021);
   - the notched DEVELOPMENT budget (ADR 0030);
   - `G17.non-dogbone` at `DEVELOPMENT_VERIFIED` (ADR 0031).

   The release accepts them as recorded.
3. **Claim ceiling.** `ClaimLevel` has three members and stops at
   `HOLDOUT_VERIFIED`. No source file names a sealed-release claim, and a
   bundle that claims anything else is refused on load
   (`tests/test_release_claim_ceiling.py`). There are two bundles:
   `dogbone-v1-s13c-cp-freeze` (`HOLDOUT_VERIFIED`, manifest `009db9d3…`) and
   `notched-v1-cp-freeze` (`DEVELOPMENT_VERIFIED`, manifest `3749f4be…`). They
   are not part of the Python distributions. G18 loads both and checks their
   claims.
4. **Licences** (decided). [Upstream sources](upstream-sources.md) records
   every adapted component. The shipped operators re-implement the author's MIT
   repositories, and no upstream line is copied. The five GINOT-derived spike
   modules are not licensed for redistribution, so they leave the tree. They
   are pinned and fetched on demand. At the owner's request they were also
   removed from the whole Git history (`git filter-repo`). Evidence written
   before the rewrite keeps its original commit ids, which resolve through
   `artifacts/release/HISTORY-REWRITE.json`. The signed notched S14 protocol
   freezes `campaigns/notched_v1/s13_close.py`, so that file is not changed:
   re-running the notched G13 lineage check reports the pre-rewrite revisions
   as absent. The recorded G13 PASS stands.
5. **Naming.** The README states that the name PI-GINOT does not claim a
   faithful reproduction of GNOT or GINO, and gives the served
   `architecture_id`, `pi-ginot-energy-parametric-film-v1`.
6. **Citation** (decided). `CITATION.cff` names Betim Bahtiri (name only),
   the repository and the upstream references, and validates against CFF
   1.2.0.
7. **Install from TestPyPI** (pending the owner's run).
   `.github/workflows/release.yml` publishes on a `v*` tag or by hand with the
   secret `TEST_PYPI_API_TOKEN`. It then installs `piginot[runtime]==0.1.0`
   from TestPyPI on Linux, macOS and Windows and runs
   `scripts/release_smoke.py` on each. The three JSON results are recorded in
   `artifacts/release/TESTPYPI-INSTALL.json` with the run URL.
8. **Lockfile.** `uv.lock` is generated by `uv lock` (uv 0.8.17). CI and the
   release workflow run `uv lock --check`, which fails whenever the lock
   differs from what the tool generates.
9. **Changelog and tag.** `CHANGELOG.md` records 0.1.0. The annotated tag
   `v0.1.0` marks the release commit. The owner pushes it, because the owner
   pushes to GitHub.
10. **Human sign-off** (decided). The decision owner read `docs/limitations.md`
    and confirmed that every sentence is true of the code as built. The answer
    is recorded in `artifacts/release/LIMITATIONS-SIGNOFF.json`, which names
    the file's digest. A later edit of the page needs a new sign-off.
11. **Repository** (decided 2026-10-09). The release is published from a new
    repository, `github.com/BBahtiri/verified-neural-operators`, which holds
    only the rewritten history. `README.md`, the user guide, `CITATION.cff`,
    `pyproject.toml` and `CHANGELOG.md` name it, and the tag `v0.1.0` moves
    to the commit that does. The project, the package and the command keep
    the name PI-GINOT (`piginot`). The S0–S8 gate records link to CI runs of
    the former repository, `BBahtiri/PI-GINOT-Agentic-Framework`. Recorded
    evidence is not edited; the per-job results are in the records
    themselves.
